# H-17 native media: two complete-candidate intake gaps closed

**Agent 22 | 22 November 2026 | Implemented and regression-tested; original K04 and K08 unresolved**

## Distinct failure mechanisms addressed

**K04: OLE/CFB input silently lost its entire candidate surface.** In `work/h17_k04_binary_window_intake.py`, an OLE-compound file was classified as a container and excluded from raw scanning, while the walker had branches only for ZIP, TAR and GZIP. Consequently every original 16-byte coupon present in the raw bytes of a native OLE/CFB spool/workbook would have been invisible to this scanner. It now treats such files as raw scannable sources. The same scanner can recognize exact 16-byte coupons represented as ASCII hex, UTF-16LE/BE hex, 16 two-digit hex groups with ordinary separators, or canonical padded Base64, as well as raw 16-byte windows. Every representation is checked against both original K04 SHA-256 reduction paths: direct component and source payload XOR published route mask. No altered commitment, guessed producer, or state extrapolation is involved.

**K08: original workbook picture and caption fields were disconnected from the exact phrase test.** The source bookmark references `R:/Stores/consumables/mug-stock.xls`; source-stage K08 research has identified M10 as a *conditional* image/caption coordinate, while it has not authenticated a particular original workbook or photo. The decoder in `work/h17_ax7782_k08_phrase_intake.py` already checked every normalized contiguous phrase against the original HMAC/SHA-256 commitment, and existing helpers already decoded BIFF8 OfficeArt shapes, BLIPs and LibreOffice-converted workbook images. However, neither original native M10 shape names/descriptions and embedded BLIP image bytes nor converted M10 image bytes reached that phrase checker.

The dispatcher now admits only the exact named `mug-stock.xls` and the original M10 anchor. It yields original OfficeArt `wz_name`/`wz_description` strings, SHA-256-verified native image bytes referenced by an M10 shape, and, where necessary, SHA-256-verified LibreOffice-converted M10 images. Original image bytes take precedence; matching converted image bytes are deduplicated. Image metadata and optional OCR then feed the unchanged K08 normalized-phrase HMAC comparison. The direct OfficeArt route also works when the converter is unavailable. Neither the source workbook nor acceptance files are modified.

## Source-literal image-bit continuation

The original source-stage `A TEAL BIT / LOW IF EVEN` reading already had a frozen, two-layout decoder in `work/h17_k08_teal_bit_image_scan.py`. The M10 image bridge now reuses exactly those two layouts on the verified original M10 image bytes: teal/cyan pixels in row-major order; absolute pixel parity selects green/blue bit plane 0/1; both channels pass through the existing byte-alignment and ASCII/UTF-16 printable-run extractor. Those recovered text runs feed the existing exact HMAC comparison. This operation is **exploratory** when applied to a workbook M10 picture because the original N14/Gabriel image-to-Emily-final link remains unauthenticated.

An end-to-end positive fixture creates an original BIFF8 M10 OfficeArt BLIP PNG with **no caption in ordinary metadata** and hides the entire synthetic line only in the source-literal green-channel bits. The native OfficeArt reader recovers the PNG, the teal decoder returns the complete hidden line, and the unchanged K08 reduction accepts its matching **synthetic** commitment. The same original picture under a non-M10 cell anchor is excluded. This control passed [GitHub Actions run 45010248437](https://github.com/FlareZ123/workplace-v2/actions/runs/45010248437). Historical K08 remains MISSING.

## Original REC8/1 end-to-end assembly

It runs the exact K04 binary/token scanner with the official component hash and route mask, runs the complete K08 native/OfficeArt/image/teal/caption decoder with the official nonce and digest, and combines unique complete hits with the six accepted source values. It calls the unchanged `resources.verify.evaluate` and **returns an eight-slot candidate only if every slot and the combined commitment pass**. `work/test_h17_complete_native_recovery.py` uses independently generated synthetic commitments and source objects: a K04 component masked into a synthetic OLE spool, a complete caption in a synthetic text record, six synthetic accepted baseline slots and the correctly constructed synthetic REC8/1 combined commitment. ## Original Outlook MSG / compressed RTF whole-phrase intake

The source-authored MAIL-11/MAIL-20 full-thread/version route remains independently useful: the local redacted EMLs lack quoted history, but a native Outlook .msg archive may retain it. The existing K08 source stream walker read MSG OLE streams as opaque bytes, including the Outlook `PidTagRtfCompressed` stream `__substg1.0_10090102`; compressed bytes and in-body RTF formatting prevented a complete normalized author-caption phrase from reaching the HMAC checker.

The current `work/h17_ax7782_k08_phrase_intake.py` now recognizes that stream only inside native `.msg`, checks the LZFu/MELA header and declared decompressed-size limit (8 MiB), uses the established `compressed-rtf` decoder and `striprtf` text converter, and submits recovered plain text to the exact K08 matcher. Dependencies are optional outside the dedicated regression environment. It preserves the unmodified MSG and native streams and refuses mismatched sizes, invalid headers and over-limit declarations.

`work/test_h17_msg_rtf_phrase_intake.py` writes a synthetic compressed Outlook RTF body with a complete phrase whose words are separated by an inline **bold** RTF control. The original K08 derivation recovers a matching synthetic HMAC from stripped text. Negative controls exclude an identically shaped stream under non-MSG OLE, malformed RTF header and oversized uncompressed-size declarations. Four synthetic tests and all earlier native/Office regressions passed [GitHub Actions run 45011441570](https://github.com/FlareZ123/workplace-v2/actions/runs/45011441570). This is an independently motivated whole-text source representation path; **the original historical MAIL-11/20 native threads are absent from the export** and no source-derived K08 phrase was produced.
