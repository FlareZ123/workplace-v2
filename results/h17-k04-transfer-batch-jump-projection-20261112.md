# K04 transfer-batch jump projection

**Date:** 2026-11-12  
**Status:** Negative result for the tested conditional MT19937 alignments; no K04 candidate recovered.

## Question

Can the 1-MiB transfer chunks in the surviving transfer audit explain large gaps between contiguous 16-checkpoint bursts, allowing later transfer records to constrain the unresolved K04 printer output in the conditional p951 MT19937 model?

## Source basis and control

The existing p951 source-only model is rebuilt from the 132 intact printer packets, leaving the selected row at stages 951–954 unresolved:

- Printer basis rank: **15,365**.
- The AX-7778 16-checkpoint burst, ordered by sequence then attempt and interpreted as little-endian 16-bit values constraining the upper half of tempered outputs at stages -157 through -142, adds **130** independent equations.
- Combined basis rank: **15,495**.
- All **128** target bits at stages 951–954 remain unresolved after that bridge.

The transfer audit is pinned to SHA-256 32970ad4431a9d610cc12dcca2813f39dd8fd2e396f9e748dc94b5932cb69adf. Each transfer has eight sequence numbers, two attempts per sequence, and bytes=1048576 on each CHUNK record. The spool's final four-word packet ends at stage 966, so the first post-spool stage is 967.

## Tested schedules

The tested source-order hypothesis is AX-7781 (dry run), AX-7782 (committed), then AX-7783 (aborted). Each transfer is represented by one contiguous 16-checkpoint burst after its hypothesized bulk interval. For a uniform interval N:

    S1 = 967 + N
    S2 = 983 + 2N
    S3 = 999 + 3N

The three candidate word counts assume one 32-bit MT output per four payload bytes:

| Interpretation | N | AX-7781 start | AX-7782 start | AX-7783 start |
|---|---:|---:|---:|---:|
| One 1-MiB chunk | 2^18 | 263,111 | 525,271 | 787,431 |
| Eight 1-MiB chunks once | 2^21 | 2,098,119 | 4,195,287 | 6,292,455 |
| Sixteen 1-MiB attempts | 2^22 | 4,195,271 | 8,389,591 | 12,583,911 |

A separate dry-run-zero model places AX-7781 immediately after the spool at stage 967, then advances by 2^21 words per subsequent 8-MiB transfer. Its starts are 967, 2,098,135, and 4,195,303.

## Method

The script reconstructs the p951 symbolic basis, adds the AX-7778 bridge, and derives the degree-19,937 MT output recurrence polynomial using Berlekamp–Massey on two independent concrete states/output bits. It verifies polynomial agreement and a high-index symbolic prediction against direct MT recurrence.

GF(2) polynomial skip-ahead constructs the exact upper-16-bit output forms at each candidate burst. For each observed checkpoint bit, the script first tests whether the printer-plus-AX-7778 source basis already determines it. It then adds the actual observations to a cloned basis and checks whether any K04 target bits become determined.

## Results

| Schedule | Independently fixed checkpoint bits | Rank gained by adding observations | K04 bits fixed | Outcome |
|---|---:|---:|---:|---|
| 2^18 uniform | 0 / 768 | 768 | 0 / 128 | No independent holdout; target unchanged |
| 2^21 uniform | 0 / 768 | 768 | 0 / 128 | No independent holdout; target unchanged |
| 2^22 uniform | 0 / 768 | 768 | 0 / 128 | No independent holdout; target unchanged |
| AX-7781 dry-run-zero at stage 967 | 106 / 256 fixed for AX-7781 | Contradiction | — | Falsified |

For the dry-run-zero placement, the AX-7781 burst has **106** bits already determined by the printer-plus-AX-7778 basis: **52 match and 54 mismatch**. The model is therefore contradicted, not merely underdetermined.

For each uniform bulk-jump schedule, none of the 768 later checkpoint bits is independently fixed by the source basis. Inserting all 768 observed values is consistent and adds rank 768, but leaves the K04 target quotient completely open: **128 of 128 target bits remain unresolved**.

## Interpretation and limits

These alignments do not recover K04 and should not be used to claim a shared printer/transfer generator. The dry-run-zero placement is falsified. The uniform schedules provide no independent high-index validation and no target information.

This is not proof that no shared generator exists. The transfer records establish chunk byte counts and checkpoint values, but do **not** establish that payload bytes were generated by MT19937, that one MT output corresponds to four payload bytes, or that the queue-note/ID order is the exact generator event chronology. Per-chunk timestamps are absent. The tested schedules are bounded hypotheses, not historical facts.

Do not repeat these same 2^18, 2^21, and 2^22 alignments. Further work should seek a genuinely source-attested target-reaching carrier or a different mechanism.
