# K08 target-blind workbook-coordinate convergence: C3 and M10

**Agent 35 | 19 November 2026 | source-local structural result**

## Result

Several previously separate low-bit observations converge on ordinary spreadsheet cell-address syntax around the explicitly bookmarked legacy workbook `R:/Stores/consumables/mug-stock.xls`.

The strongest new equality is **M10**:

1. The selected note heads `ATEALBIT` have ASCII least-significant bits that pack first-bit-as-LSB to `0x4D = M`.
2. The selected PTW-417 seal serials in witness order B,D,A,C have low bits `0,1,0,1`, which pack to decimal **10**.
3. Those independent source paths therefore form **M10**.
4. Separately, K05 contains exactly two CRC-valid matching recorder rows per latch. Applying the source-derived **LOW IF EVEN** rule to the latch ordinal, lower sequence on even latches and higher sequence on odd latches, selects:
   `42BFD053 | 0A56E858 | 6FC2B743 | F01E4572`.
5. Byte LSB packing over those 16 bytes yields `0A 4D`: row **10**, column **M**, or **M10** in A1 notation.

Thus the K05 alternate retry stratum reproduces the same **M10** cell address obtained independently from the note/seal chain.

This does not alter the official K05 reducer. The official greatest-sequence-per-latch K05 component remains `FF8B78200A56E8586DCDA00EF01E4572`. Its low bits yield `03 43`, which under the same row-first / column-second representation is **C3**.

## Why the row/column reading is source-grounded

The signed WN-14 K01 source is a 16-byte sequence of four ordered ink groups:

`049A AB2E 1CDE 7A82 CD7C 6023 4303 C91A`.

Read each adjacent byte pair as **row byte, column byte**, converting the second byte to an Excel column ordinal. The eight addresses are:

- `EX4`
- `AT171`
- `HN28`
- `DZ122`
- `DT205`
- `AI96`
- `C67`
- `Z201`

All column ordinals are within legacy BIFF8's 256-column range. This is the same row-first/column-second convention that turns K05 low-bit bytes `03 43` into **C3** and `0A 4D` into **M10**.

The retired-office bookmark file supplies the relevant object directly: **Tea-room stock sheets**, `R:/Stores/consumables/mug-stock.xls`, is bookmark **#3**.

The earlier A1-cell hypothesis for K01 is therefore no longer supported only by the conditional `P212` output. The surviving K05 source itself now supplies two compact coordinate-shaped outputs, and one of them, M10, is independently regenerated by the note/seal path.

## Specificity control

Each K05 latch has exactly two valid candidate rows, giving 16 low/high retry-choice masks. Their 16-byte low-bit reductions collapse to exactly **eight distinct two-byte outputs**.

The independently derived M10 output occurs for two masks because latch 1's lower/higher alternatives share the relevant low-bit pattern. The actual source-derived LOW-IF-EVEN selection is one of those two masks, specifically low/high/low/high over latches 0..3.

This control prevents the claim that every retry combination produces M10. It also shows the M10 equality is not an artifact of simply choosing the official all-high reducer, whose output is C3.

## Dual-use archive addresses

The cell notation also aligns with the existing archive-routing interpretation:

- **C3** corresponds to the established `MAIL-03 / group C` step.
- **M10** corresponds to the established `M + 10 -> MAIL-10` step.

So the same low-bit objects can be read as both compact archive addresses and valid spreadsheet cells. This makes the missing workbook a more coherent engineered carrier hypothesis than treating those outputs as unrelated numeric coincidences.

Following the established mail route from C3 gives MAIL-03 -> MAIL-09 -> MAIL-13 -> MAIL-04 -> MAIL-10. The exact subject initials are **WRAPT**. The visual resemblance to “WRAP T” / “wrap text” is a hypothesis worth preserving for a future workbook intake; it is not used as evidence in the reproducer and does not recover any phrase.
