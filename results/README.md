## Operational intake utility

- `work/h17_ax7782_object_intake.py` is a read-only intake path for the original AX-7782 retained object (eight 1 MiB chunks). It verifies the selected transfer chain and K07 acceptance, reports common per-chunk checksum interpretations without assuming one, and inventories nested ZIP/TAR/PDF/image metadata and source-specific strings with bounded depth/size and no on-disk extraction; optional local image/scanned-PDF OCR is available with `--ocr` when Pillow, pytesseract/Tesseract, and (for PDFs) PyMuPDF are installed; embedded PDF attachments are scanned recursively. It is preparatory only: the original 8 MiB object and manifest have not been supplied, so this utility has not recovered K04 or K08.
- `work/h17_ax7782_k08_phrase_intake.py` is the exact K08 companion for that retained object. It revalidates the AX-7782 second-attempt chain and K07 commitment, then searches text extracted from the object or decoded members, including embedded printable ASCII/UTF-16 runs in binary streams and UTF-16LE/BE text decoded from conventional hex/Base64 carriers (ZIP/TAR/GZIP, MIME email, PDF text/content/annotations/attachments, image metadata, optional OCR, and OLE streams when `olefile` is installed). Each contiguous normalized span (default 1–32 words; configurable) is checked with the original desk nonce, HMAC-SHA256 truncation and K08 SHA-256 commitment. It does not paraphrase or edit wording, and never guesses PDF passwords; an authorized supplied password can be passed with `--pdf-password`. Run `python work/h17_ax7782_k08_phrase_intake.py --object /path/to/AX-7782 --resources resources --ocr --json-out /tmp/k08-intake.json`. The object is still absent, so no real-source K08 recovery is claimed.
- Focused K08 scanner tests: `python -m unittest discover -s work -p 'test_h17_ax7782_k08_phrase_intake.py'` (nine synthetic tests, including binary-embedded ASCII/UTF-16, hex/Base64 UTF-16 carriers, encrypted-PDF password handling, and original K07/K08 known-answer checks). - `work/h17_k04_binary_window_intake.py` is a read-only exact K04 search for a native spool file/directory or AX-7782 object. It scans unaligned raw 16-byte windows and standalone 32-hex tokens, checking both direct component bytes and payload XOR the published route mask; it descends into ZIP/TAR/GZIP members with byte/member/depth caps and no extraction. Run `python work/h17_k04_binary_window_intake.py --self-test` for synthetic raw/masked/ASCII-hex checks. This is an intake path, not evidence of recovery; no native spool or AX-7782 object has been supplied.
- `work/h17_sticky_notes_intake.py` is a read-only, allowlisted extractor for an authorized Sticky Notes `plum.sqlite` from the profile-refresh route. It snapshots the database and every present `-wal`, `-shm`, and `-journal` sidecar, verifies pre-copy and copied-destination hashes plus post-copy source equality, reads logical tables/rows, and separately carves printable ASCII and UTF-16LE/BE spans from all copied sidecars so deleted text still resident in pages, WAL frames, or rollback journals can be recovered. If the temporary read-only SQLite open/query fails, it returns raw-carved spans with an explicit `sqlite_error` instead of discarding them. It does not inspect browser history, credentials, cookies or network paths. Run `python work/h17_sticky_notes_intake.py /authorized/path/plum.sqlite --json-out /tmp/plum-intake.json`; focused tests: `python -m unittest discover -s work -p 'test_h17_sticky_notes_intake.py' -v` (eight synthetic tests, including WAL recovery, copy-race rejection, rollback-journal capture, and unreadable-database raw fallback). Focused local harnesses pass; the full committed test module has not yet been run end-to-end in this shell. This helper has not been run against the missing AX-7782/profile-refresh source; it is an intake capability, not a K08 recovery claim.
