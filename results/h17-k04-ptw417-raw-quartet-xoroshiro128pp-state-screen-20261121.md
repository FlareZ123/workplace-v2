## Question

The source-selected PTW-417 signed CLOSED/AS_LEFT serial quartet is a raw 16-byte object. The K04 source route separately identifies PS-261003-0417 and its last ACK/RECOVER payload. The shared 417 suffix is only a candidate join, not proof of a common issuer. A distinct, inexpensive producer hypothesis is that the raw quartet initializes a 128-bit xoroshiro128++ state whose first two 64-bit outputs form the 16-byte coupon payload.

This differs from (a) testing the serial quartet itself as the coupon, (b) testing the accepted K03 digest as a PRNG state, (c) direct/hash/CPython-MT production of the PS-0417 payload, and (d) the rolling PTW-390..416 state screen, which explicitly held out PS-0417.

## Method

Use the standard xoroshiro128++ 1.0 transition/output function to generate two consecutive 64-bit outputs. Test only the source-selected B,D,A,C quartet, with these serialization views:

- each 4-byte serial as recorded or reversed;
- the two 64-bit state halves in original or swapped order;
- big- or little-endian interpretation of each state half;
- big- or little-endian serialization of each output word;
- original or reversed order of the two output words.

This is 32 complete configurations. For each, check:
1. exact equality with the selected PS-0417 ACK2 payload;
2. SHA-256 of the generated 16 bytes directly against the K04 commitment (generated bytes treated as the component);
3. SHA-256 of generated bytes XOR the route mask against the K04 commitment (generated bytes treated as the coupon payload).

Raw source bytes, candidate blocks, route mask, and target digest are not reproduced in this report.
