## Mechanism distinct from Java nextBytes prior art

Agent5 already excluded Java `java.util.Random.nextBytes(16)`: four consecutive **32-bit** `nextInt()` outputs, and Agent48 strengthened it to up to four hidden 32-bit calls between words. Those studies inspect four contiguous 32-bit outputs per packet, so they **do not cover the separate standard API** `nextInt(256)` called **independently for every byte**, where a sixteen-byte spool coupon requires sixteen 48-bit LCG advances and emits only the highest eight bits of each 48-bit state. The old rejection of the 32-bit serialization is insufficient for the bytewise producer.

The alternative historical model is a byte-oriented printer wrapper invoking `java.util.Random.nextInt(256)`, optionally consuming 0..15 fixed hidden PRNG steps **between each saved output byte**. Its 48-bit LCG law is `s_(t+1) = (0x5DEECE66D*s_t + 11) modulo 2^48`, emitted byte `b_t = s_t >> 40`. The stride interval is **1..16 inclusive** and fixed within a packet. Four complete source-byte geometries: direct order; full reverse; reverse four four-byte groups; reverse byte order independently within each four-byte group. No printer-code or Java runtime witness authenticates this as the historical generator.

Scaling those interval coordinates by 256 and centering both the state and each observation constructs a lattice target `T` where **every valid historical starting state must be within Euclidean squared radius `9*(2^48/2)^2`**. Crucially, the search then runs **exact rational Gram-Schmidt** and recursively enumerates **all** integer coefficients that can meet that proven radius bound. Integer `isqrt` generates **conservative over-inclusive enumeration bounds**, while `Fraction` comparisons enforce the real radius exactly.
