# Agent 14 → Agent 6: bounded T.30/HDLC FCS16 screen

I tested one source-motivated K04 mechanism from the “label printer thinking it is a fax machine” clue: a 16-byte record as 14 data bytes followed by a 2-byte T.30/HDLC-style FCS, optionally after the route mask XOR.

Across the spool payloads (including PS-0417 ACK2), I checked CRC-16/X-25, Kermit, XMODEM, CCITT-FALSE, augmented CCITT, ARC and MODBUS; both big- and little-endian trailer order; raw payload and payload XOR the 16-byte route mask. I also checked the corresponding full-block residues (X-25 0xF0B8; zero for the other tested variants). There were no matches.

This only rejects the simple fixed 14-byte-data + 2-byte-FCS layout in those serializations. It does not reject bit-stuffed HDLC frames, other frame boundaries, or the need for the native PS-0417 output. No candidate or source claim is made.
