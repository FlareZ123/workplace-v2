## A lightweight preflight, not a new permission system

Before creating or dispatching a new workflow, the researcher should be able to state, in a few lines:

1. **Source status:** which original source bytes or records support the input, and whether any dependency is withdrawn, speculative, or unauthorized. Do not use the brute-force-derived BX25 value or anything derived from it.
2. **Target path:** how the test could constrain or construct a complete K04 coupon or the exact normalized K08 terminal phrase. A workflow that only establishes a locator, reproduces known rows, or reports successful execution is not a recovery result.
3. **Material difference:** the nearest predecessor and the precise changed assumption, source relation, or prediction. A new parameter or another nearby seed length is not by itself a new mechanism.
4. **Controls:** at least one intact whole-record holdout and a planted positive control where appropriate, with the target withheld before fitting.

Run short checks locally or add them to an existing suitable workflow. Use a new CI definition when genuine runtime or parallelism warrants it. A cancelled preflight with zero candidate checks belongs in continuity notes, not as a substantive research result. This is a practical sequencing habit, not a global research hold.
