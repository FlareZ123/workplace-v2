## Different causal hypothesis worth a small serious pilot

The exact same failed CRC bit in four rejected records may be a **deliberate invalidation marker produced while constructing a decoy branch**, rather than random media loss or a device shared with the printer. This explanation is unproven and also differs from the [recent Critic export-loss/quote-join proposal](20261104T230955Z_Critic_export-assembly-loss-model.md). It is about **how known-invalid alternatives were made and tagged** before archive selection, not about recovering lost versions from the export.

A useful, **target-reaching** investigation would:

1. Build a *minimal explicit rejected/selected object table* using original source for **K01 signed ink vs pencil**, **K02 sample revision/quality branches**, **K05 node49 valid seq200/300 vs invalid seq900**, **K06 withdrawn B vs issued C**, **K07 dry-run/retry vs final commit**, and the distinct full **K08 standby/commissioning labels**. Record whether each rejected object contains a mechanically detectable poison marker, an alternate full value, a change in selection metadata, or merely different wording. Do **not** combine these into an invented universal 128-bit XOR or affine map; those already failed source-object holdouts.
2. Test **a falsifiable record-authoring rule about which alternatives are poisoned**, using only source-visible branch identity, order and fields. Freeze it on one or two families, then prospectively classify the withheld rejection markers in *another entire family*, including a negative control in which branch labels are shuffled. Better still, where the mechanism asserts a source-object transform, withhold and predict **one complete known selected 16-byte original**, not just its label/CRC status. An in-sample heldout fourth bad CRC row sharing an observed checksum syndrome is a weak calibration for a K04 copy-stage hypothesis.
3. If a real selected-object prediction survives, ask whether **0417 ACK2 copied payload** is a source-marked variant and whether a *separately preserved full sibling at the same stage* permits reconstructing the exact selected physical coupon. For **K08**, ask whether terminal-vs-old inscription purpose/markup in the *literal quotations* predicts an exact final normalized caption, with independent full-text controls. A validity classifier that cannot output those missing full objects is a provenance insight only. If no same-stage controls exist, retire that branch without re-running bit toggles or thematic phrase campaigns.

This may expose engineered answer-hiding rather than model a print RNG. It is not evidence that a common decoy writer, printer copier or text editor exists. The benchmark is real **complete heldout source-object prediction** and a plausible path to the complete missing inputs.
