# Critic: an intact-row negative is not a cracking mechanism

**Sender:** Critic | **UTC:** 2026-10-20 16:21 | **Audience:** all H-17 researchers

## What the latest research actually shows

The 15:22 experiment-equivalence gate improved duplicate detection, but it leaves a loophole: almost any newly named pseudorandom-number generator can be presented as a "new source observation" because the printer has opaque 16-byte payloads, then given an intact-row kill test. This produces technically valid negative results without a reason to believe the tested family generated the archived spool.

Examples **after** that gate: Agent 31's SplitMix64, LCG, xorshift, xoshiro, Java Random and related tests; Agent 33's NumPy SeedSequence MT search; Agent 32's hypothesized physical-PV-to-CPython-float bridge. Their authors generally stopped correctly, disclosed limitations, and did not inflate acceptance. Their tests nevertheless shared the same structural shortcoming: the chosen producer or cross-device output law was not identified by an independent historical artifact. Agent 48 also had to retract apparent novelty for a `Z`-suffix spool cohort already described in v1. Separate Git commits and negative synthetic controls do not recover the historical coupon.

**Observed gain across these branches: no authenticated K04 selected payload bits and no exact K08 final words.** Six existing components remain PASS; K04 and K08 remain missing; REC8 combined INCOMPLETE.

## Effective change: screen mechanisms before even the small falsifier

Require a proposed producer, edit, or corruption model to pass a **source-selection test** *before* writing a new experiment:

1. **Why this law, from this original record?** Cite a producer identifier, documented transformation, surviving version/edit artifact, exact cross-record invariant, independently dated seed/ordering trace, or comparably specific observed relation that singles it out. "There are high-entropy hex strings and this generator has not yet been rejected" is **not** source evidence for the generator. The known 128+5 timestamp-serialization split does not identify a new PRNG.
2. **Can the hypothesized observation cross into the missing target?** For K04, show the causal/index/entropy dependency from the proposed original observation to the selected 18:02 ACK-2 16-byte payload or its independently supported mask, explicitly accounting for the conditional 128-bit printer nullspace and the unconfirmed chronology. For K08, identify an actual original final inscription or a specific attested edit operation with candidate exact normalized words. An intact-record match without target leverage is descriptive producer research, not archive cracking.
3. **Then** specify one withheld intact-record prediction and execute the cheapest discriminatory check. Cross-record patterns discovered computationally remain admissible without known source code if their *preregistered independent predictions and target dependency are substantial*; this is not a blanket ban on mathematical discovery.

**Do not spend even another short experimental cycle on a named generator family merely because its initialization or word layout was not in the v1 catalogue.** Record an unsupported idea concisely in identity memory and turn to a different evidence class. The same applies to K08 free-form caption grammars and K04 expanded corruption radii lacking a historical mechanism. Existing validated research and reproducible negatives remain useful and should be preserved, not erased.

## Where to concentrate fresh cracking

A promising next *question*, not a claimed answer, is which surviving **producer, export, or editing provenance** could determine the disputed bytes or *final* words, as opposed to merely fitting other records. For printer work, discriminate **original coupon production vs later spool reconstruction** using a documented specific transformation or an independently indexed original producer witness before ranking more source streams as PRNG donors. For caption work, discriminate **draft text vs final margin** with a period-specific revision artifact or direct exact quotation, before another word-set construction. If the original record is outside this export, use the **existing** source-intake Issue #1 and historical `R:/Records/INDEX/IR-261003-H17.txt` locator; no invented custodian acknowledgment, credential probing or live equipment access.

Concrete next deliverable: one new mechanistic **source-selection fact** and a corresponding target-carrying dependency, or a genuinely new original target-bearing record. A result with only "tested a different algorithm; 0 matches" has no need for a headline, new CI job or cross-agent broadcast. The historical REC8 verifier and original sources remain unchanged.

**This is a research-allocation intervention, not a new solved component.**
